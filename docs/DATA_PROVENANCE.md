# Data Provenance — CERT r4.2 → Percentile-30 → 60/20/20 User Split

**Status:** CANONICAL (documented per approved decision D3, 2026-08-11)
**Scope:** This is the authoritative statement of how every dataset used by this project was produced. Wherever data provenance is relevant (reports, thesis, reproduction instructions), it must be represented consistently with this document.

---

## 1. Provenance chain

```text
Raw CERT r4.2 logs
        ↓
MIT feature-extraction script
        ↓
preprocessed dayr4.2.csv
        ↓
MIT temporal-representation script
        ↓
percentile-30 representation
        ↓
60/20/20 user split
        ↓
downstream experiments
```

## 2. Authoritative statements

1. The preprocessed **`data/dayr4.2.csv`** was generated by running the **MIT feature-extraction script** on the raw CERT r4.2 logs.
2. The percentile-30 files — **`data/dayr4.2-percentile30.pkl`** (and the derived `dayr4.2-percentile30-{train,validation,test}.pkl`) — were generated by our team using the **MIT temporal-representation script** on the preprocessed `dayr4.2.csv`.
3. The **entire preprocessed dataset was converted to the percentile-30 representation BEFORE the 60/20/20 user split**.

## 3. What this means (and does NOT mean)

- The percentile transformation is **NOT train-only**. Percentiles were computed on the full dataset prior to splitting. Do **not** claim the percentile transformation was fit on training data only.
- This is the actual methodology and is documented as-is. It is not retroactively changed, and no new preprocessing pipeline is introduced.
- Leakage controls that DO apply: the train/validation/test split is strictly **user-level** (600/200/200 users, 42/14/14 malicious, seed 42, zero user overlap); per-modality feature scalers are fit on train users only; Tier-2 thresholds/weights were selected on validation only; the test split was evaluated once.

## 4. Freeze policy (per D3)

- Do **NOT** regenerate the percentile-30 dataset.
- Do **NOT** modify the percentile-30 files.
- Do **NOT** retrain models.
- Do **NOT** alter the Tier-1 methodology because of this provenance.
- Do **NOT** introduce a new preprocessing pipeline.

The goal of this document is to **document the actual provenance**, not to change it.
